Exercise 02

Debugging CSS

Three findings are documented with the original declaration, correction, and explanation.

My Debugging Analysis

01

Declaration formatting: missing semicolon

Original: color: red

Correction: color: red;

Reasoning: A semicolon clearly terminates a declaration and makes later edits safer. Because this is the last declaration in the rule, the browser may still parse it correctly; I will distinguish code-quality improvement from a demonstrated rendering defect when I inspect it.

02

Heading hierarchy: one size for three levels

Original: h1, h2, h3 { font-size: 2.5em; }

Correction: h1 {font-size:2.5rem} h2 {font-size:1.8rem} h3 {font-size:1.25rem}

Reasoning: Separate sizes preserve a visible hierarchy between page title, section title, and subsection. This is a design issue rather than invalid CSS; the computed sizes should be checked in the browser.

03

Declaration formatting: missing semicolon

Original: box-sizing: border-box

Correction: box-sizing: border-box;

Reasoning: The terminator makes the declaration consistent and reduces editing mistakes. As with finding 1, a final declaration can parse without a semicolon, so the evidence should report what DevTools actually shows.

Corrected CSS

body {
  font-family: "Times New Roman", serif;
  margin-inline: 20%;
  text-align: justify;
  background: ivory;
  color: darkred;
}

h1 { color: #b00000; font-size: 2.5rem; margin: 20px 0; }
h2 { color: #b00000; font-size: 1.8rem; margin: 20px 0; }
h3 { color: #b00000; font-size: 1.25rem; margin: 20px 0; }

.container {
  width: 100%;
  padding: 20px;
  box-sizing: border-box;
}

a { color: #0000ff; text-decoration: underline; }

Goal: At a 900px viewport, make a selected panel's rendered outer width exactly 420px without using width: 420px.
